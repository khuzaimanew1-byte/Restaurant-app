Refactor the Employee Management system to a production-ready architecture using Neon PostgreSQL as the Single Source of Truth (SSOT).

SSOT RULES

* Database is the authoritative source of employee data.
* No duplicated employee state.
* No hardcoded employee records inside components.
* No component-specific employee sources.
* No local employee records after successful save.
* All pages must render from fetched database data.
* All employee operations must go through a centralized service/repository layer.

DATABASE ARCHITECTURE

Create:

1. employee_profile
   Static employee information.

2. employee_status
   Dashboard/runtime employee information.

Relationship:

employee_status.eid → employee_profile.id

Use proper foreign key constraints and indexes.

* Show timings when available.

Do not derive status from displayed times.

SUBMIT FLOW

Create Employee:

1. Validate form.
2. Upload/store image.
3. Insert employee_profile record.
4. Get created employee id.
5. Create linked employee_status record.
6. Clear local draft.
7. Invalidate employee queries/cache.
8. Redirect to dashboard.
9. Dashboard must fetch fresh data from database.
10. Newly created employee card must appear automatically.
