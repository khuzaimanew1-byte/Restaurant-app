# ⚙️ 3. GLOBAL OPTIMIZATION RULES (CONDITIONAL EXECUTION ONLY)

Optimization rules only activate IF feature exists in SSOT.

## 📌 Images / Media (FUTURE CONDITIONAL RULE)

If images exist in system:
- Compress before storage
- Use CDN/external storage
- Lazy load on visibility
- Use thumbnails in lists
- Never store raw binaries in DB or memory

If images do NOT exist:
- No image logic exists in runtime
- No memory allocation for unused media

Rule:
"Optimization only applies when feature exists."

---

## 📌 Popups / Modals (HYBRID RULE)

If popups exist:
- Mount when triggered
- Keep soft-mounted while recently used (hidden allowed for fast reuse)
- Auto-destroy if unused for a set time or on navigation
- Never keep permanently hidden popups in memory
- All popup lifecycle must be controlled via a single manager, 120s soft time
- Always reset timer on when re-open and start time when close

If not defined in SSOT:
- No popup system exists

# ⚡ 4. CODE OPTIMIZATION + CLEAN ARCHITECTURE RULES (CRITICAL)

## 🔥 DRY (DON’T REPEAT YOURSELF) ENFORCEMENT

- Never repeat logic
- If logic is reused → create a function
- If behavior is repeated → abstract into reusable module
- If variation exists → pass parameters instead of duplicating code

Rule:
"Same logic must never exist twice."

---

## 🧠 DEAD CODE ELIMINATION RULE

- Remove unused functions immediately
- Remove unused variables, imports, styles
- No orphan code allowed
- No commented unused blocks in production

Rule:
"If it is not used, it must not exist."

---

## 🔁 DUPLICATE LOGIC HANDLING

- If logic is slightly different:
  → DO NOT duplicate entire code
  → Extract core function
  → Pass variation as parameter

Rule:
"Variation ≠ duplication. It is parameterization."

# 🧬 11. IDENTIFIER MINIFICATION & SAFE NAMING OPTIMIZATION SYSTEM

This system supports compact identifier generation for performance optimization in compiled/production builds only.

Core principle:
"Short identifiers are allowed only when system stability, uniqueness, and maintainability are guaranteed."

---

## 📌 1. CORE RULE

All internal identifiers (where applicable) may be transformed into compact representations during build/compilation phase.

This includes:
- Variables
- Functions
- Classes
- Style tokens
- Component keys
- Internal module references
- Asset logical identifiers (not physical files)

NOT included:
- External APIs
- Database schemas (unless explicitly compiled layer)
- User-generated content
- Security tokens / hashes

---

## ⚙️ 2. SAFE MINIFICATION STRATEGY (FIXED)

### ✔ PRIMARY GOAL:
Minimize identifier length WITHOUT causing:
- collisions
- ambiguity
- debugging loss

---

### 📌 RULE A — PREFERRED SHORT IDENTIFIERS

Use shortest safe identifiers in this priority:

1. Single-character identifiers ONLY when scope is isolated
2. Two-character identifiers for shared scope
3. Three-character identifiers for global/shared systems
4. Expand only when uniqueness cannot be guaranteed

---

### 📌 RULE B — CONTROLLED CHARACTER SET

Allowed characters:
- a-z
- A-Z
- 0-9
- _ (underscore only for grouping)

❌ Hyphens NOT allowed in identifiers (to prevent parsing issues)

---

### 📌 RULE C — SCOPE-BASED LENGTH CONTROL

Identifier length depends on scope:

- Local scope → 1–2 chars allowed
- Module scope → 2–3 chars
- Global scope → 3+ chars minimum for safety

---

## 🧠 3. COLLISION PREVENTION SYSTEM (CRITICAL FIX)

Before assigning any identifier:

- System MUST check uniqueness in current scope
- If collision risk exists:
  → increase length instead of reusing characters
  → generate next safe variant

Rule:
"No two active identifiers may share same representation in same scope."

---

## 🔁 4. EXPANSION RULE (SAFE SCALING)

If identifier space is exhausted:

- Increase length by +1 character
- Maintain prefix grouping for readability
- Ensure deterministic generation (no randomness in production)
---

## 🧬 5. DEVELOPMENT VS PRODUCTION RULE

### Development Mode:
- Fully readable names
- No minification applied

### Production Mode:
- Safe minification applied
- Debug mapping (source map equivalent) MUST be preserved
- No loss of traceability

Rule:
"Optimization must never remove debug traceability."

---

## 🎨 6. STYLE & CLASS MINIFICATION (SAFE VERSION)
